# Registry (PEN Global) — Design Notes

These are the product/architecture decisions for the PEN Global
"Registry Module" refactor. The README only links here so a reviewer
who wants the *why* can find it; everyone else can ignore this.

### Mapping

The "Registry" stakeholder team in the brief isn't a separate code role —
it lives inside the merged `ADMIN` role on `/admin`. The Registry
team's four jobs are:

- Owns the catalogue of **Programmes** (`/admin/programmes`).
- Issues **Student IDs** in `SMS-YYYY-####` format, per school per
  year. Auto-generated by `nextStudentId` in `lib/sequences.ts`; the
  `(schoolId, admissionNo)` unique index guarantees race-safety.
- Manages the **enrollment lifecycle** —
  `enrolled / deferred / withdrawn / completed`. Old values
  (`active / graduated / transferred / dropped`) are mapped in
  `prisma/migrations/20260102000000_…/migration.sql`.
- Sets the **programme-based fee structure** that `createInvoice`
  auto-derives from when no explicit `feeStructureId` is supplied.

### Data model

Programme-based end-to-end. `Student` belongs to a `Programme`,
`FeeStructure` is attached to a `Programme` (with `classId` retained
as an optional sub-scope), every `Invoice`'s amount is derived from
`student.programme → active FeeStructure`.

### Re-numbering

Existing `ADM-*` admission numbers were inconsistent across schools
and years. They were re-numbered to `SMS-YYYY-####` per school per
year in the same migration that introduced `Programme`. Sequencing is
inside `prisma.$transaction` and relies on the unique index for
race-safety (not row locks — uniqueness is what guarantees it).

### How to test

See [`REGISTRY_TEST_GUIDE.md`](./REGISTRY_TEST_GUIDE.md) for a
numbered, hands-on script. The Vitest integration suite
(`npm test`) covers the action layer:

- `createStudent` — atomic happy path, email uniqueness, cross-school
  class rejection, missing programme rejection, sequential
  `SMS-####` auto-generation.
- `createProgramme` — happy path + audit, duplicate code per school,
  cross-school guard.
- `programmeFees` — `createFeeStructure` with `programmeId`,
  `createInvoice` auto-derives amount, refusal when no amount is
  derivable.
